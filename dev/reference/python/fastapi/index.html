    Not legal advice

    dpdpkit is software that helps you implement obligations under India's Digital Personal Data Protection Act, 2023 and the DPDP Rules, 2025. It does not provide legal advice and does not guarantee compliance.

    DPDPKit ¶

    DPDPKit(*, principal_resolver: PrincipalResolver, admin_guard: AdminGuard | None = None, db_url: str | None = None, repository: Repository | None = None, config: str | Path | Mapping[str, Any] | None = None, policy: str | Policy | None = None, overlays: Iterable[str] = (), registry: Registry | None = None, notifier: Notifier | None = None, contact: Mapping[str, str] | None = None, contact_resolver: ContactResolver | None = None, identity_verifier: IdentityVerifier | None = None, signing_key: bytes | str | None = None, tenant_id: str = 'default', webhooks: Iterable[WebhookEndpoint] | None = None, migrate_on_startup: bool = False, create_tables: bool = False, **kit_kwargs: Any)

    Wire dpdpkit into a FastAPI app.

    webhooks are delivered through a database outbox (see dpdpkit.fastapi.webhooks); when omitted they are read from the webhooks: list in the config, with secrets from secret_env.

    principal_resolver(request) returns a stable, non-personal reference for the signed-in user (for example the user's primary key), or None. admin_guard(request) returns a role (viewer/handler/admin), True for admin, or None/False for no access.

    start_scheduler ¶

    start_scheduler(*, retention_minutes: int = 15, verify_hour: int = 2, root_export_hour: int | None = 3, root_sinks: Iterable[RootSink] = (), webhook_seconds: int = 30) -> Any

    Run retention every retention_minutes, ledger verification daily at verify_hour and a root-hash export daily at root_export_hour UTC (None disables it) (APScheduler).

    The export writes to each of root_sinks and publishes ledger.root_exported; subscribe a webhook to that event to hand a copy to a third party. Due webhook deliveries are sent every webhook_seconds when any endpoint is configured.

    webhooks ¶

    Durable outbound webhooks: a database outbox with retries, backoff and a dead-letter state.

    Publishing an event only inserts one row per matching endpoint, so request handlers never wait on the network. WebhookOutbox.deliver_due (run by the scheduler) sends due rows, reschedules failures with exponential backoff, and marks a row dead after max_attempts. Dead rows stay until someone redelivers them; nothing is dropped silently.

    Receivers verify X-DPDPKit-Signature with dpdpkit.events.verify_signature and should treat the event id as an idempotency key: a delivery can arrive more than once.

    WebhookOutbox ¶

    WebhookOutbox(repository: SqlAlchemyRepository, endpoints: Iterable[WebhookEndpoint], *, clock: Callable[[], datetime], sender: Sender = urllib_sender, max_attempts: int = 10, base_delay: timedelta = timedelta(seconds=30), max_delay: timedelta = timedelta(hours=2), lease: timedelta = timedelta(minutes=5), batch_size: int = 100)

    max_attempts sends spaced base_delay * 2**n apart (capped at max_delay): with the defaults, 10 attempts over roughly 4 hours. lease stops two workers sending the same row.
